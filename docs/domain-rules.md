# 领域边界

支持药店跨门店健康计划、用药随访、应急保供和安全事件闭环。

现有领域资料与后端围绕以下边界组织：

- 顾客授权：服务计划入组，健康记录、提醒、跨店续接三项授权独立授予与撤回
- 健康计划版本：用药计划只能递增发布，高风险调整经另一名有权限人员复核后落版
- 用药与库存：预留→领取→退回→报损→调拨全程流水对账；召回批次可售为零
- 随访转诊：随访结论与安全结论、转诊建议、不良反应上报与处置
- 安全事件复核：高风险调整双人复核、召回批次四处拦截（预留/领取/调拨出/到货入）
- 购药决策：提前领取、疗程重叠、替代品牌、召回批次输出允许/阻断/转人工与原因
- 时间与补录：occurred_at 与 recorded_at 分离，晚到信息只影响之后的建议
- 协调与恢复：到期随访、召回、ADR 回访、调拨到货合并为待联系任务，快照持久化

资料版本只能递增。参与方、事实和约束均不能为空，示例不得包含真实个人信息、账号或凭据。

## 不可破坏的规则

1. 普通店员不可见健康内容；健康访问必须角色、资质、授权三者同时成立并写访问日志。
2. 服务终止后新的健康访问立即失败；历史记录不删除、可按历史时点回放。
3. 召回批次在任何通道（含应急保供、在途到货）都不得出库或上架。
4. 高风险调整未经第二人复核不得产生生效的用药计划版本。
5. 补录必须保留真实发生时间；任何截至 T 的判断不得纳入 T 之后入库的信息。
