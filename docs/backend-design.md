# 药店健康管理后端设计

后端围绕五条主线组织：授权与访问、临床记录、购药决策、库存台账、协调与视图。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `src/entities.py` | 角色、授权范围、计划、药品批次、台账事件、任务等核心实体 |
| `src/errors.py` | 领域异常（未找到、校验、越权、授权缺失、计划状态） |
| `src/store.py` | 内存仓储、审计日志与查询辅助 |
| `src/access.py` | 角色权限 + 顾客授权的双重门禁 |
| `src/plans.py` | 服务计划建档、分别授权、终止与重启 |
| `src/clinical.py` | 医嘱摘要、用药计划、观察、随访、转诊、不良反应、调整复核 |
| `src/consultation.py` | 跨店咨询：定位当前有效计划与最近安全结论 |
| `src/dispensing.py` | 购药决策：允许、阻断或转人工及明确原因 |
| `src/inventory.py` | 批次库存台账：预留、领取、退回、报损、调拨、召回、对账 |
| `src/tasks.py` | 随访、召回、调拨的统一待联系工作清单 |
| `src/views.py` | 顾客视图、店员物流看板、药师建议依据、合规追溯 |

## 关键规则

### 授权与访问

- 顾客按范围分别授权：健康记录、提醒、跨店续接；授权可撤销。
- 健康数据访问要求：角色权限（药师/安全质量人员）+ 计划有效 + 对应授权在有效期。
- 普通店员只有物流权限（领取、配送）；营销人员无任何健康数据权限。
- 服务终止时全部授权撤销，新的健康访问立即被拒绝；既有交易与安全处置
  保留在台账和审计日志中，安全质量人员可依法追溯。

### 临床记录与复核

- 药师资质（执照、有效期）登记在案，过期即失去临床写入权限。
- 用药计划版本递增；高风险调整（高风险药品或曾发生不良反应的药品）
  进入待复核状态，由另一名有权限人员复核后才生效，复核人不能是提出人。
- 随访结论与用药调整记录依据的观察及当时的授权快照，作为说明建议
  依据（授权、药品、观察、执业责任）的材料。

### 时间模型

- 真实发生时间（occurred_at / measured_at）与系统录入时间（recorded_at）
  分离；断网后补录保留真实发生时间。
- 晚到的补录信息只影响其录入时间之后的建议：`observations_known_at`
  按录入时间限定可见范围，既有建议的引用保持不变。

### 购药决策

- 召回批次 → 阻断；未登记批次 → 转人工。
- 提前领取（剩余可覆盖天数超过宽限）、疗程重叠（计划内同成分药品在用）、
  替代品牌（同成分非计划药品）→ 转人工，并给出明确原因。
- 应急保供只放宽依从性类提示，批次风险（召回、未登记）一律不得绕过。

### 库存台账

- 入库、预留、释放、领取、退回、报损、调拨全部以追加式台账记录，
  任意时点可按门店与批次对账，并与实物盘点比对。
- 召回批次禁止预留、领取与调拨；召回时释放未履约预留，并为已领取
  顾客生成召回联系任务。

### 协调与视图

- 到期随访、批次召回、门店调拨共用待联系工作清单；任务按来源去重，
  互相关联以便协调为一次联系；服务重启后待联系顾客不丢失。
- 顾客视图只呈现当前方案与下一步；店员看板只含物流事项；
  药师可调用建议依据说明每一次专业判断。
