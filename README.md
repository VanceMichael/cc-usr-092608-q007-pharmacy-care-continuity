# 药店健康管理与用药连续服务

支持药店跨门店健康计划、用药随访、应急保供和安全事件闭环。

## 参与方与事实

主要参与方包括顾客、执业药师、门店工作人员、连锁运营人员、安全质量人员。领域资料记录以下已经确认的事实：

- 实体药店正在从价格零售转向健康管理和价值服务
- 政策提出强化专业服务、健康促进与应急保供功能并建设健康驿站
- 药店可承担全周期健康管理、用药依从性陪伴和突发状态保供

## 业务约束

- 健康授权
- 药师执业范围
- 跨店续接
- 疗程重叠
- 召回批次
- 库存预留

`contracts/context.schema.json` 描述资料结构，`fixtures/context.json` 提供不含真实身份信息的示例，`src/pharmacy_context.py` 负责读取和校验这些资料。

## 后端模块

`src/` 下实现药店健康管理后端，覆盖服务计划授权、临床记录、购药决策、
库存台账与协调视图：

- `plans.py`：顾客选择服务计划并分别授权（健康记录、提醒、跨店续接），
  终止与重启服务
- `access.py`：角色权限与顾客授权双重门禁，普通店员仅物流事项，
  营销人员不接触健康信息
- `clinical.py`：药师资质、医嘱摘要、用药计划、测量观察、随访结论、
  转诊建议、不良反应报告；高风险调整由另一名有权限人员复核
- `consultation.py`：跨店咨询先定位当前有效计划与最近安全结论
- `dispensing.py`：识别提前领取、疗程重叠、替代品牌、召回批次，
  给出允许、阻断或转人工的明确原因；应急保供不绕过批次风险
- `inventory.py`：预留、领取、退回、报损、调拨的批次台账与对账
- `tasks.py`：到期随访、批次召回、门店调拨的统一待联系清单，
  重启服务不丢失待联系顾客
- `views.py`：顾客当前方案与下一步、店员物流看板、药师建议依据说明、
  终止后的合规追溯

详细设计见 `docs/backend-design.md`。

## 开发命令

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

编译检查：

```bash
python3 -m compileall -q src
```

两条命令只读取仓库内文件，不需要连接外部业务系统。
